# Internationalisation

- Langues : `src/i18n/config.ts` (au départ `['fr']`, défaut `fr`). Ajouter une langue = un fichier `src/i18n/ui/<lang>.json` + des textes dans `formula-texts/<lang>/` et `exercise-texts/<lang>/` + une entrée dans config. Aucune autre modification de code ne doit être nécessaire : c'est le test de l'architecture.
- URLs : toujours préfixées par la langue (`/fr/...`). `/` redirige vers la langue par défaut.
- Segments de route localisés (formules/formulas…) : table `routeSegments` dans `src/i18n/config.ts` + fonction `localizedPath(lang, routeKey, params)`. Ne jamais écrire une URL à la main.
- Pages : `src/pages/<lang>/<segment localisé>/…` sont des fichiers fins qui importent une vue de `src/views/`.
- Chaînes d'interface : `src/i18n/ui/fr.json`, clés plates et typées (`t(lang, 'nav.formulas')`). Pas de concaténation de phrases : variables `{count}`. Pluriels via `Intl.PluralRules` (suffixes `.one` / `.other`).
- Contenu manquant dans une langue → repli sur `fr` + bandeau `fallback.notice`.
- Nombres/dates via `Intl` avec la langue courante. Saisie numérique : accepter `,` et `.`.
- `<html lang dir>` renseignés ; CSS en propriétés logiques ; hreflang sur chaque page ayant des traductions.
- Les identifiants de formule/exercice sont communs à toutes les langues.
